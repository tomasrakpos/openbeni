# راه‌اندازی حساب کاربری، مدل‌های سایت و پنل ادمین

این راهنما قدم‌به‌قدم توضیح می‌دهد چطور Supabase را بسازید، متغیرها را ست کنید،
migration را اجرا کنید، اولین ادمین را تعریف کنید و اولین پرووایدر/مدل را از پنل
`/admin` اضافه کنید.

> نکته‌ی امنیتی: هیچ کلید واقعی (کلید پرووایدر، service key، master key) نباید در کد،
> ریپو، اسکرین‌شات یا چت نوشته شود. همه‌ی کلیدها فقط در متغیرهای محیطی سرور (و در
> پنل Cloudflare) قرار می‌گیرند.

---

## ۰) معماری در یک نگاه

- **Supabase**: Auth (ایمیل/رمز) + Postgres + RLS + Realtime. فقط هویت کاربر،
  کاتالوگ پرووایدر/مدل و متادیتای مصرف اینجاست.
- **Cloudflare Pages Functions** (`functions/api`): ورود/ثبت‌نام، دریافت لیست مدل،
  پروکسی استریم چت و همه‌ی endpointهای ادمین. کلید پرووایدر و service key فقط اینجا
  خوانده می‌شود.
- **مرورگر**: چت‌ها و پیام‌ها همچنان در IndexedDB محلی می‌مانند. کلیدهای شخصی (BYOK)
  مثل قبل با رمزنگاری محلی ذخیره می‌شوند.

جریان چت با مدل‌های سایت:

```
مرورگر → POST /api/chat (فقط model + messages)
        → بررسی نشست + نقش + سقف مصرف + اعتبارسنجی ورودی
        → انتخاب کلید سالم از pool + رمزگشایی AES-GCM
        → درخواست به پرووایدر (OpenAI/Anthropic/Gemini)
        → نرمال‌سازی استریم به SSE و برگرداندن به مرورگر
        → ثبت متادیتای مصرف (بدون متن پیام)
```

## ۱) ساخت پروژه‌ی Supabase

1. به <https://supabase.com> بروید و یک پروژه‌ی جدید بسازید (Region نزدیک کاربران).
2. از **Project Settings → API** سه مقدار را بردارید:
   - `Project URL` → `SUPABASE_URL`
   - `anon public key` → `SUPABASE_ANON_KEY` و `VITE_SUPABASE_ANON_KEY`
   - `service_role key` → `SUPABASE_SERVICE_ROLE_KEY` (فقط سرور!)
3. از **Authentication → Providers → Email** مطمئن شوید Email فعال است.
4. اگر می‌خواهید ثبت‌نام با تأیید ایمیل باشد (توصیه‌شده برای جلوگیری از ثبت‌نام انبوه):
   **Authentication → Sign In / Providers → Email → Confirm email = ON**.
   در این حالت کاربر بعد از ثبت‌نام باید ایمیل را تأیید کند. (اگر OFF باشد، بلافاصله
   وارد می‌شود و محافظت اصلی همان rate limit سرور است.)
5. برای Realtime (به‌روزرسانی لحظه‌ای لیست مدل‌ها) نیازی به تغییر خاصی نیست؛
   کانال عمومی `catalog` به‌صورت پیش‌فرض کار می‌کند. اگر در پروژه‌تان Realtime خاموش
   است، در **Database → Replication / Realtime** آن را فعال کنید. در بدترین حالت،
   کلاینت هر ۶۰ ثانیه و هنگام بازگشت به تب، لیست را دوباره می‌گیرد.

## ۲) اجرای migration

1. در داشبورد Supabase به **SQL Editor** بروید.
2. محتوای فایل `supabase/migrations/0001_init.sql` را کامل کپی و اجرا کنید.
3. این فایل می‌سازد:
   - `profiles` (نقش، وضعیت، سقف روزانه/ماهانه)
   - `app_settings` (ثبت‌نام باز/بسته، سقف پیش‌فرض)
   - `providers`، `provider_keys` (فقط ciphertext)، `catalog_models`
   - `usage_events` + ایندکس‌ها + view/RPC مصرف
   - RLS: هر کاربر فقط ردیف خودش را می‌بیند؛ جدول‌های ادمین برای `anon/authenticated`
     هیچ policy ندارند و فقط service role به آن‌ها دسترسی دارد.
   - تریگر ساخت پروفایل در اولین ثبت‌نام.

> اگر بعداً migration را دوباره اجرا کنید، دستورات `if not exists` و
> `create or replace` امن هستند.

## ۳) ساخت master key برای رمزنگاری کلیدها

در ترمینال:

```bash
openssl rand -base64 32
```

خروجی را در `MASTER_ENCRYPTION_KEY` بگذارید.

- همین مقدار باید همیشه ثابت بماند. اگر عوض شود، کلیدهای ذخیره‌شده قابل رمزگشایی
  نیستند و باید از پنل ادمین دوباره وارد شوند.
- این مقدار را در جای امن (مثلاً password manager تیم) نگه دارید.

## ۴) تنظیم متغیرهای محیطی

### الف) اجرای محلی

فایل `.env.example` را به `.env` کپی کنید و مقادیر را پر کنید:

```env
SUPABASE_URL=https://YOUR-PROJECT.supabase.co
SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
ADMIN_EMAILS=you@example.com
ADMIN_PASSWORD=یک-رمز-قوی-حداقل-۸-کاراکتری
ADMIN_SESSION_SECRET=یک-رشته-تصادفی-دلخواه
MASTER_ENCRYPTION_KEY=...
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=...
```

سپس:

```bash
npm install
npm run dev
```

### ب) Cloudflare Pages

در **Cloudflare Dashboard → Workers & Pages → پروژه → Settings → Environment variables**
(برای Production و در صورت نیاز Preview) این‌ها را اضافه کنید:

| متغیر | محیط | توضیح |
| --- | --- | --- |
| `SUPABASE_URL` | سرور | آدرس پروژه |
| `SUPABASE_ANON_KEY` | سرور | برای تأیید توکن |
| `SUPABASE_SERVICE_ROLE_KEY` | سرور (Secret) | دسترسی کامل دیتابیس؛ هرگز به مرورگر نرود |
| `ADMIN_EMAILS` | سرور | ایمیل ادمین‌ها با کاما (برای ورود با حساب Supabase) |
| `ADMIN_PASSWORD` | سرور (Secret) | رمز صفحه‌ی جداگانه‌ی `/admin` (حداقل ۸ کاراکتر) |
| `ADMIN_SESSION_SECRET` | سرور (Secret) | اختیاری؛ کلید امضای توکن ادمین |
| `MASTER_ENCRYPTION_KEY` | سرور (Secret) | کلید AES-GCM |
| `VITE_SUPABASE_URL` | Build | در زمان build داخل باندل می‌رود |
| `VITE_SUPABASE_ANON_KEY` | Build | کلید عمومی anon |

متغیرهای `VITE_*` باید در مرحله‌ی **Build** هم موجود باشند، چون Vite آن‌ها را در
زمان build جایگزین می‌کند. در Cloudflare معمولاً همان متغیرهای محیطی برای build و
runtime استفاده می‌شوند.

> هرگز `SUPABASE_SERVICE_ROLE_KEY` یا `MASTER_ENCRYPTION_KEY` یا کلید پرووایدر را با
> پیشوند `VITE_` ذخیره نکنید.

## ۵) ورود به پنل ادمین

پنل ادمین یک **صفحه‌ی جداگانه** است و هیچ لینک یا گزینه‌ای به آن در سایت عمومی وجود
ندارد. فقط رمز آن را می‌دانید و آدرسش را مستقیم باز می‌کنید:

1. در `.env` (یا متغیرهای محیطی هاست) مقدار `ADMIN_PASSWORD` را ست کنید (حداقل ۸
   کاراکتر). `ADMIN_SESSION_SECRET` اختیاری است؛ اگر خالی باشد خود رمز، توکن‌ها را
   امضا می‌کند و تغییر رمز همه‌ی نشست‌های قبلی را باطل می‌کند.
2. سرور را دوباره اجرا/دیپلوی کنید.
3. <https://YOUR-DOMAIN/admin> را باز کنید و رمز را وارد کنید.
4. پس از ورود، تب **Providers** را باز کنید و پرووایدر و کلیدها را اضافه کنید.

نکات امنیتی:

- رمز فقط روی سرور بررسی می‌شود؛ در باندل مرورگر هیچ رمزی نیست.
- توکن ورود با HMAC-SHA256 امضا می‌شود، ۸ ساعت اعتبار دارد و فقط در
  `sessionStorage` همان تب نگه داشته می‌شود.
- تلاش‌های ورود به ازای هر IP محدود است (۵ تلاش در ۱۵ دقیقه).
- اگر رمز را فراموش کردید، `ADMIN_PASSWORD` را عوض کنید و دوباره دیپلوی کنید.

### ادمین با حساب Supabase (اختیاری)

اگر ترجیح می‌دهید ادمین با حساب Supabase هم وارد شود، همان ایمیل را در
`ADMIN_EMAILS` بگذارید یا در SQL نقش را ست کنید (فقط با service role یا از
SQL Editor):

```sql
update public.profiles set role = 'admin' where email = 'you@example.com';
```

### پیش‌نمایش محلی بدون Supabase

اگر هنوز Supabase را تنظیم نکرده‌اید و فقط می‌خواهید پنل را ببینید:

```bash
npm run dev
```

سپس <http://localhost:5173/admin> را باز کنید و رمز `ADMIN_PASSWORD` را وارد کنید. پنل
با **داده‌ی نمونه** نمایش داده می‌شود (پرووایدرها، کلیدهای ساختگی، کاربرها، نمودار مصرف
و تنظیمات) و یک نوار زرد بالای صفحه می‌گوید «حالت پیش‌نمایش محلی». داده‌ها فقط در
`localStorage` همان مرورگر می‌مانند.

- این حالت فقط در `npm run dev` وجود دارد و در build نهایی حذف می‌شود؛ پس
  `/admin` روی سایت واقعی همیشه رمز واقعی می‌خواهد.
- به‌محض ست کردن `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`، پیش‌نمایش خودبه‌خود
  خاموش می‌شود و دیتابیس واقعی استفاده می‌شود.
- دکمه‌ی «خروج از پیش‌نمایش» داده‌های نمونه را پاک می‌کند.

## ۶) افزودن اولین پرووایدر و مدل‌ها

1. وارد `/admin` شوید و تب **Providers** را باز کنید.
2. «افزودن پرووایدر» را پر کنید:
   - نام نمایشی (مثلاً `OpenAI`)
   - Base URL معتبر و **https** (مثلاً `https://api.openai.com/v1`)
   - فرمت API: OpenAI-compatible / Anthropic / Gemini
   - یک یا چند کلید (هر خط یک کلید)
3. ذخیره کنید. کلیدها همان لحظه با AES-GCM رمز می‌شوند و دیگر نمایش داده نمی‌شوند؛
   فقط «N از M کلید سالم» دیده می‌شود.
4. روی **تست اتصال** بزنید:
   - سرور `GET /models` را از خود پرووایدر می‌گیرد.
   - سپس با هر مدل یک درخواست واقعی کوچک می‌فرستد.
   - فقط مدل‌هایی که واقعاً پاسخ داده‌اند به‌عنوان verified ذخیره می‌شوند.
5. در همان کارت، بخش **مدل‌ها** را باز کنید، مدل‌های موردنظر را فعال کنید و در صورت
   نیاز نام نمایشی را تغییر دهید.
6. تغییرات بلافاصله برای همه‌ی کاربران آنلاین broadcast می‌شود و لیست مدل‌های چت
   بدون رفرش به‌روز می‌شود.

### چرخش خودکار کلید

- اگر کلیدی `401/403/429/402/5xx` یا timeout بدهد، همان درخواست به‌صورت خودکار با
  کلید بعدی تکرار می‌شود؛ کاربر فقط پاسخ نهایی را می‌بیند.
- کلید خطادار برای مدتی (۱۰ دقیقه برای auth، ۱۵ دقیقه برای سهمیه، ۱ دقیقه برای
  rate limit و…) از چرخه خارج می‌شود و بعد خودکار برمی‌گردد.
- شماره‌ی کلید و دلیل خطا در لاگ سرور ثبت می‌شود، نه متن پیام و نه خود کلید.

## ۷) کاربرها، سقف مصرف و آمار

- تب **Users**: جستجو بر اساس نام/ایمیل، فیلتر وضعیت، مسدود/آزاد کردن، و تعیین سقف
  توکن روزانه/ماهانه برای هر کاربر (خالی = استفاده از پیش‌فرض).
- تب **Usage**: نمودار مصرف روزانه، مصرف به تفکیک مدل و پرووایدر، پرمصرف‌ترین
  کاربرها و تعداد خطاها (بازه‌ی ۷/۳۰/۹۰ روز).
- تب **Settings**: باز/بسته کردن ثبت‌نام و سقف پیش‌فرض روزانه/ماهانه.

وقتی کاربر به سقف برسد یا مسدود شود، پیام خطای دوستانه می‌بیند (بدون نام پرووایدر یا
کلید).

## ۸) چه داده‌ای ذخیره می‌شود؟

- در Supabase: ایمیل، نام نمایشی، تاریخ ثبت‌نام، آخرین فعالیت، وضعیت، نقش، سقف‌ها و
  **متادیتای مصرف** (کاربر، مدل، پرووایدر، توکن ورودی/خروجی، وضعیت، زمان، تأخیر).
- **متن پیام‌ها و پاسخ‌ها هرگز ذخیره نمی‌شود.** چت‌ها فقط در IndexedDB مرورگر
  می‌مانند.
- در لاگ سرور فقط شماره‌ی کلید و نوع خطا ثبت می‌شود.

این توضیح در صفحه‌ی ثبت‌نام هم به کاربر نشان داده می‌شود.

## ۹) بررسی نهایی و تست

```bash
npx.cmd tsc -b --noEmit
npx.cmd vitest run
npx.cmd vite build
```

تست‌های جدید: رمزنگاری/رمزگشایی AES-GCM، چرخش کلید و cooldown، بررسی نقش ادمین،
ورود با رمز ادمین و اعتبار/انقضای توکن، اعتبارسنجی Base URL و ریدایرکت SSRF،
محاسبه‌ی مصرف/سقف و اعتبارسنجی بدنه‌ی چت.

## ۱۰) عیب‌یابی سریع

| نشانه | علت احتمالی | راه‌حل |
| --- | --- | --- |
| «User accounts are not configured» | env سرور ست نشده | `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را ست و دوباره deploy کنید |
| ورود خطای ۴۰۱ می‌دهد | ایمیل تأیید نشده یا رمز اشتباه | صندوق ایمیل را چک کنید؛ در Auth → Users وضعیت را ببینید |
| `/admin` رمز را قبول نمی‌کند | `ADMIN_PASSWORD` ست نشده/عوض شده یا رمز اشتباه است | مقدار را در env ست/اصلاح و سرور را دوباره اجرا کنید |
| لیست مدل خالی است | مدلی enable نشده یا تست اتصال اجرا نشده | در پنل، تست اتصال بزنید و مدل‌ها را فعال کنید |
| خطای «temporarily unavailable» | همه‌ی کلیدها در cooldown هستند یا کلید نامعتبر است | کلید جدید اضافه کنید یا تست اتصال بزنید |
| چت ۴۰۱ می‌دهد | نشست منقضی شده | از منوی حساب خارج و دوباره وارد شوید |
| تغییرات پنل فوری نمی‌رسد | Realtime خاموش است | Realtime را فعال کنید؛ تا آن زمان polling ۶۰ ثانیه‌ای کار می‌کند |
| ثبت‌نام بسته است | در Settings خاموش شده | از تب Settings روشن کنید |

## ۱۱) نکات امنیتی مهم

- اگر قبلاً کلیدهای Coarena یا هر کلید دیگری را جایی به اشتراک گذاشته‌اید، آن‌ها را
  در پنل پرووایدر باطل/چرخش کنید.
- CORS فقط روی دامنه‌ی خودتان تنظیم می‌شود (`ALLOWED_ORIGIN`)؛ wildcard وجود ندارد.
- Base URLهای ادمین فقط `https` عمومی هستند؛ localhost/IP خصوصی و ریدایرکت به آن‌ها
  مسدود است.
- rate limit روی ثبت‌نام (۵ در ساعت به‌ازای IP)، ورود (۱۰ در ۱۵ دقیقه) و چت
  (۳۰ در دقیقه به‌ازای IP و ۶۰ در دقیقه به‌ازای کاربر) اعمال می‌شود.
- برای محافظت بیشتر در برابر ثبت‌نام انبوه، تأیید ایمیل Supabase را روشن نگه دارید یا
  Cloudflare Turnstile را جلوی مسیر `/api/auth/signup` قرار دهید.
